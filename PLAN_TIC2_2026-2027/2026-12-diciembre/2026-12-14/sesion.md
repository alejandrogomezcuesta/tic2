**Unidad:** T2, Git y control de versiones. **Saberes:** TICO.2.A.2.5. **Criterio:** 5.2.

## Teoría breve
Git conserva la historia del proyecto. El flujo basico es working tree, `add`, staging, `commit` y `push`. Un commit debe representar un cambio pequeno y tener mensaje claro.

**Enlace original:** [Tema 2, 2.4](https://lopegonzalez.es/eso-y-bachillerato/tic-ii-2o-bachillerato/tema-2-ingenieria-del-software/#24-control-de-versiones)

## Desarrollo de 60 minutos
- 0-8: que problema resuelve una version anterior.
- 8-20: demostración local con `git init`, `status`, `add`, `commit` y `log`.
- 20-45: equipos versionan un proyecto de práctica y hacen tres commits.
- 45-55: recuperar un archivo desde el historial sin borrar el proyecto actual.
- 55-60: interpretar `status` y escribir el siguiente commit.

## Tarea
Crear un repositorio de la app con README y tres commits descriptivos. Entregar captura del historial o salida de `git log`.

**Evidencia:** historial. **Apoyo:** hoja de comandos. **Ampliación:** `.gitignore` y rama de funciónalidad.
